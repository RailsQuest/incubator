Here's a distilled version of the team coding conventions, focusing on the essentials while preserving important information:

# Team Conventions

## Core Principles
- DRY, KISS, Composition over Inheritance, Explicit over Implicit
- Small steps, one at a time
- Wait for feedback before implementing new features

## Code Organization
- Prefer meaningful names and single responsibilities
- Favor duplication over overloaded responsibilities

## Rails Guidelines
- Follow Rails conventions
- Use shared partials and Tailwind for consistent styling
- Use `rails restart` instead of `rails server`
- Keep ChromeDriver updated
- ALWAYS use Rails generators for new components

## Testing
- Use Minitest with comprehensive coverage
- Organize tests logically, use fixtures for test data

## Version Control & Code Review
- Write clear, atomic commits
- Review for adherence to guidelines and overall code quality

Remember: This is a living document, update as practices evolve.
